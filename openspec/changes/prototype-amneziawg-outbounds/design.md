## Context

Существующие движки отдают GRoute локальный SOCKS5. Фабрика туннелей, маршрутизатор и правила резервирования уже умеют работать с такими выходами.

## Decisions

- В Windows отделить движок в `groute-awg.exe`. Передавать конфигурацию и учётные данные локального прокси по анонимным каналам. Проверять версию протокола до передачи профиля. Обновлятор берёт groute-awg.exe из стабильных выпусков awg-vX.Y.Z проекта benny52/GRoute и проверяет SHA-256 из данных GitHub, версию файла и протокол обмена. Для отдельного выпуска собирается ./cmd/groute-awg с параметром Go -ldflags "-X main.helperVersion=vX.Y.Z" и к тегу прикладывается groute-awg.exe для Windows amd64. Интерфейс отдельно сверяет библиотеку с официальными тегами Amnezia. Копии разных версий хранятся раздельно.

- Явно поддерживать экспорт 3x-ui с Base64-кодированным клиентским файлом внутри `vpn://`. Для `amneziawg://` поддерживать ту же полезную нагрузку.
- Использовать официальный amneziawg-go и виртуальный TCP/IP-стек в памяти процесса. Назначения подключений передавать в этот стек через локальный SOCKS5. Внешний адрес peer исключать из перехвата до первого пакета.
- Подтверждать доступность участием удалённого peer в криптографическом обмене. Передавать изменение состояния обычному механизму резервирования.
- Сохранять параметры в дополнительном поле профиля. Приватный, предварительно согласованный и ключ защиты заголовка обрабатываются хранилищем секретов. У существующих профилей поле отсутствует.
- Для воспроизведения использовать два независимых peer с одинаковым внутренним адресом назначения и разными ответами. Остановить только серверную сторону приоритетного peer, оставить его клиент и правило активными.

## Risks / Trade-offs

При прерывании пути теряется открытое TCP-соединение. Доступность запасного проверяется для новых потоков и для следующих UDP-датаграмм. Тестовый стенд не требует изменения сетевых интерфейсов Windows.

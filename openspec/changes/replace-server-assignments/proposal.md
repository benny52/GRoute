## Why

Пользователь настраивает один профиль «Работа» и хочет сохранить правила YouTube и Telegram при смене подписки. Также ему нужно одним действием задать этим правилам общий приоритетный сервер, хотя сейчас у каждого свой. Предложение по пунктам 1 и 7 [ТЗ](../../../docs/PROJECT_SPEC.md) для портативного клиента Windows. Логика замены и названия согласованы 12 ноября 2026 г.

## What Changes

### Как пользователь назначает сервер

Основной сервер пользователь выбирает только на главной странице. В правиле поле «Приоритетный сервер» предлагает список. Например:

1. Основной сервер
2. Vless-Ger
3. Xhttp-swe

«Основной сервер» всегда стоит первым, даже при пустом выборе на главной. Этот пункт означает, что правило следует выбору на главной. При выборе «Vless-Ger» по имени правило сохраняет его ID. Выбор любого пункта меняет только назначение правила. Поле «Запасной сервер» позволяет задать один или несколько серверов по порядку.

В профиле «Работа» нажать «Групповое изменение» → «Приоритетный сервер» → выбрать server4 → отметить YouTube и Telegram → «Применить». Перед применением видны обе строки: server1 → server4 и server2 → server4. Оба сохраняют свой запасной сервер server3. Указывать старый сервер не требуется. Чтобы назначить запасные серверы, пользователь выбирает «Запасной сервер», задаёт порядок, отмечает правила и нажимает «Применить». Предлагаем заменять весь список отмеченных правил с показом прежних и новых позиций. Адресная замена одного старого сервера также остаётся доступной. По умолчанию видны правила текущего профиля, переход ко всем профилям явный.

### Что объяснит мастер

Для каждого пункта «Через VPN» мастер показывает поле «Приоритетный сервер». Сразу над выбором, в существующей подсказке шага:

- **Основной сервер** вы выбираете на главной. Оставьте этот пункт в правиле, если хотите, чтобы правило следовало за выбором на главной.
- **Приоритетный сервер** — через него правило сначала пытается установить соединение. Если выбрать сервер по имени, он останется закреплён за правилом при смене основного.
- **Запасной сервер** подключается заранее. Если приоритетный недоступен, новые соединения смогут пойти через запасной. Несколько запасных проверяются в заданном порядке.

На шаге «Итог» для наследующего правила показывается «Приоритетный сервер — Основной сервер (сейчас Vless-Ger)», для закреплённого — «Приоритетный сервер — Vless-Ger». При пустом основном мастер сообщает «Основной сервер пока не выбран».

### Что покажет главная после подключения

В существующем блоке «Работающие серверы» под именем и состоянием появляется короткая строка причины. Например, «Приоритетный сервер в 3 правилах» у Vless-Ger и «Запасной сервер в 5 правилах» у Xhttp-swe. Если один сервер выполняет обе роли, видны оба числа. Для наследования выводится отдельная причина, например «Основной сервер для 2 правил». Маршрут «Всё остальное», группа и локальный прокси подписываются отдельно, когда именно они требуют запустить сервер. Смена основного или правил обновляет пояснения. Показанный запасной может ждать первого соединения через него.

### Что происходит при удалении SUB1

Подписка принадлежит клиенту. В профиле правил хранится выбор её серверов. В примере SUB1 содержит server1, server2 и server3, других серверов нет, на главной выбран server1.

| Правило в профиле «Работа» | До удаления SUB1 | После подтверждения |
| --- | --- | --- |
| Локальная сеть | Напрямую | Напрямую |
| YouTube | Приоритетный — server1, запасной — server3 | Приоритетный — Основной сервер, запасных нет |
| Telegram | Приоритетный — server2, запасной — server3 | Приоритетный — Основной сервер, запасных нет |

Текст подтверждения: «Удалить подписку SUB1 и 3 сервера? YouTube и Telegram переключатся на основной сервер с главной. Запасной сервер server3 будет удалён из обоих правил. Основной сервер сейчас входит в SUB1. После удаления он будет пуст». Кнопки «Удалить подписку» и «Отмена». При работающей маршрутизации VPN-правила ждут сервер без выхода напрямую. Пользователь добавляет любой новый сервер, выбирает его на главной, и оба правила используют его для новых соединений. Повторно открывать редактор правил не требуется.

Если удаляемый сервер был только запасным сервером, его убирают из цепочки, сохраняя приоритетный сервер и порядок прочих запасных серверов. Если уже есть сохранённые профили, их затронутые правила добавляются в то же подтверждение. Дополнительный сценарий: в неактивном профиле «Дом» server3 стоит вторым запасным сервером между B и C. После удаления останутся B → C. При адресной замене server3 на D получится B → D → C. В группах и локальных прокси могут быть отдельные ссылки; их результат показывается до подтверждения.

### Как это связано с пунктом 8

Для ручной копии и дубликата из новой подписки есть конкретная замена. Например, если новый сервер соответствует server1 по параметрам подключения, тот же обход найдёт выбор на главной, явный приоритетный сервер YouTube, запасные серверы, группы и прокси, включая неактивные профили. После подтверждения явные ссылки перейдут на новый ID, а наследующие правила сохранят «Основной сервер». Распознавание дублей при импорте и их учёт при повторном обновлении относятся к пункту 8.

## Capabilities

### New Capabilities

- `server-assignments` — просмотр, замена и наследование назначений VPN-серверов.

### Modified Capabilities

Действующих спецификаций возможностей в этой копии пока нет.

## Impact

Go-контроллер, хранилище профилей и граница Wails отвечают за просмотр и согласованную запись. Интерфейс правил, мастер и карточка отображают один и тот же результат расчёта. Точки реализации и способ восстановления описаны в [design.md](design.md), критерии приёмки — в [spec.md](specs/server-assignments/spec.md).

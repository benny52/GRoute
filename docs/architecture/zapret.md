# Обход DPI (zapret2)

«Обход DPI» (`internal/zapret`, `internal/app/zapret.go`, файл `zapret.json`) запускает рядом с
движком HyRoute `winws2.exe` из [bol-van/zapret2](https://github.com/bol-van/zapret2) v1.0.7. Он
обрабатывает трафик, который HyRoute отправляет напрямую: YouTube, Discord и свои сайты открываются
без VPN. Только Windows.

## Соседство с движком

- winws2 открывает свой хэндл WinDivert с приоритетом 0 (по умолчанию), движок HyRoute — с
  приоритетом 1000 ([interception.md](interception.md#сосуществование-с-zapret-goodbyedpi-и-другими-программами-на-windivert)).
  Direct-пакеты HyRoute реинжектит, и они доходят до winws2; Tunnel-пакеты превращаются во входящие к
  relay и до winws2 не доходят. Поэтому обход действует только на прямой трафик, а туннель он не
  портит.
- Трафик Hysteria и Xray к серверам исключён из хэндла HyRoute и winws2 его видит. Каждый профиль
  winws2 получает `--ipset-exclude` со списком адресов работающих серверов: SNI REALITY может
  совпасть с доменом из списков. Список переписывается при каждом изменении статуса подключения;
  winws2 сам перечитывает изменённые файлы списков.
- Драйвер общий: `WinDivert64.sys` в архиве zapret2 тот же файл, что у HyRoute (тот же SHA-256).
  `WinDivert.dll` у winws2 своя, из того же архива.
- winws2 работает, пока обход включён, независимо от подключения. Он стартует в job-объекте HyRoute с
  `KILL_ON_JOB_CLOSE` (`hysteria.StartChild`): после выхода или падения HyRoute не остаётся.

## Правила

HyRoute держит правила «Обход DPI: …» наверху активного профиля правил, все «Напрямую»: YouTube и
Discord (домены из `lists.go`), «Discord (голос)» (`Discord.exe`, UDP 19294–19344 и 50000–50100) и
«Свои сайты». `syncZapretRules` через `editRules` ставит их наверх, если набор или порядок
отличается. Выключенное пользователем правило остаётся выключенным. Применяется при сохранении
настроек обхода, при запуске и после смены профиля правил.

## Безопасность командной строки

- Ни один текст пользователя не попадает в аргументы winws2. `--lua-init` выполняет код Lua с
  правами администратора, а `zapret.json` лежит в папке, куда пишет пользователь. Командная строка
  собирается только из проверенных блоков (`Build`): методы — по ID из `Methods`, свои сайты — в
  файл hostlist, и только строки из букв, цифр, `-` и `.` (`NormalizeSite`).
- Пустой hostlist в winws2 означает «все сайты», поэтому пустой список получает `example.invalid`.
- Файлы (`winws2.exe`, `cygwin1.dll`, WinDivert, три библиотеки Lua, два фейковых пакета) не входят в
  архив HyRoute: антивирусы часто считают winws2 вредным. При первом включении HyRoute скачивает
  официальный zip релиза, сверяет его SHA-256 и SHA-256 каждого файла из `build/deps.json` и
  раскладывает их в `runtime\zapret\` (`lua\`, `blobs\`) защищённой папки
  (`runtimefiles.ZapretFromDeps`, `Stage`). Списки лежат в `%ProgramData%\HyRoute\zapret`, тоже
  защищённой (`core.ProtectDir`).

## Профили winws2

Для каждого сервиса, которому нужен обход в этой сети:
- TLS (TCP 80, 443; у своих сайтов ещё HTTP) по hostlist сервиса: метод или круговой перебор;
- QUIC (UDP 443): фейковый Initial;
- у Discord ещё голос (UDP 19294–19344, 50000–50100, L7 `discord,stun`, пакет `discord_ip_discovery`,
  фейк QUIC) и медиа-TLS на портах 2053, 2083, 2087, 2096, 8443.

**Методы** (`Methods`) переложены с пресетов [Zapret 2 GUI](https://github.com/TheFirstNoob/Zapret-2-GUI)
(MIT): фейк ClientHello google.com с занижённым TCP timestamp или TCP MD5, `multisplit` с
`seqovl`, `multidisorder`, `fakedsplit`, `hostfakesplit`.

**План** сервиса (`PlanFor`): метод, выбранный вручную, — один; «Не нужен» или подбор, показавший,
что сервис не блокируется, — профиля нет; иначе круговой перебор, начиная с методов, которые подбор
нашёл рабочими в этой сети (`Picked.Working`, быстрые первыми), затем остальные. Если ни одному
сервису обход не нужен, winws2 не запускается.

**Круговой перебор** (`circular` из `zapret-auto.lua`), порядок как в мануале zapret2:
`--out-range=-s34228 --in-range=-s5556 --lua-desync=circular:fails=3:retrans=2[:nld=2] --in-range=x
--payload=tls_client_hello <методы со strategy=N>`. Фильтр `--payload` стоит **после** `circular`:
winws2 применяет его и к оркестратору, и с фильтром перед ним (так в пресетах Zapret 2 GUI и zapret2UI)
`circular` не видит входящих RST от DPI и ответов сервера, которые сбрасывают счётчик неудач, —
остаётся только детектор повторов ClientHello. `--in-range=x` снимает входящие пакеты с методов.
Неудача: 2 повтора ClientHello, RST в первых 4 КБ ответа или HTTP-редирект на заглушку; успех —
больше 4 КБ ответа. 3 неудачи за 60 с — следующая стратегия, по кругу. Счётчик хранится по
хосту из SNI; `nld=2` у YouTube и Discord сводит его к домену второго уровня, иначе каждый из сотен
серверов `*.googlevideo.com` переключался бы сам по себе. У своих сайтов `nld` нет (для
`example.co.uk` это был бы `co.uk`). Заморозку соединения после первых ~16 КБ (ТСПУ) детектор не
видит: её ловит только проверка подбора.

## Подбор

`ZapretPick` (под `zapretMu`, отменяемый) не останавливает обход пользователя. Проверки идут с
**фиксированных локальных портов**: 13 слотов по 150 портов начиная с 30000 (ниже динамических портов
Windows). Основной winws2 получает `--wf-raw-filter=not (<все слоты>)` и пакеты проверок не видит;
тестовый winws2 метода i получает `--wf-raw-filter=<слот i>` и видит только их. winws2 добавляет этот
фильтр через AND к своему, отличающийся фильтр не задевает защиту от двух копий с одним фильтром.
Идея с портами взята у nfqws2-keenetic-strategy-selector и blockcheckw: там так же параллельно
проверяют стратегии на роутерах (через метки и порты iptables/nftables).

1. **Без обхода** (слот 0): каждый сервис проверяется, и для заблокированных ставится диагноз —
   худшая из неудач его адресов:
   - `dns` — имя не находится;
   - `dns-stub` — имя указывает на локальный или зарезервированный адрес (заглушка провайдера);
   - `ip` — соединение не устанавливается (блок по адресу или сервер лежит);
   - `cert` — чужой сертификат;
   - `tls` — рукопожатие сброшено или без ответа (DPI по SNI);
   - `freeze` — после рукопожатия соединение обрывается или замирает (ТСПУ, «16–20 КБ»);
   - `no-answer` — ответ 5xx.

   Обойти можно только `tls` и `freeze` (`Bypass`); остальное страница предлагает пустить через VPN.
2. **Все методы сразу**: на каждый метод свой winws2 (свой слот) с одним методом на все
   заблокированные сервисы, 1,5 с на запуск, затем проверки всех слотов параллельно. Метод, чей winws2
   не запустился, считается неработающим; не запустился ни один — ошибка.
3. Результат пишется в `Picked[ключ сети]`: `Methods` — самый быстрый метод, `Working` — все рабочие
   по времени (при равенстве — в порядке библиотеки). Ключ: `id:<NLM ID>` опознанной сети, иначе
   `gw:<MAC шлюза>`, иначе `""`. Хранится не больше 32 сетей (старые вытесняются). Методы, которых
   эта версия не знает, отбрасываются при загрузке. После подбора основной winws2 перезапускается с
   новым порядком.

**Проверка** (`Prober`): сама разрешает имя (IPv4 первым), подключается с порта своего слота (порт
занят — следующий), делает TLS-рукопожатие с отпечатком Chrome (`refraction-networking/utls`,
`HelloChrome_Auto`: ТСПУ может обращаться с рукопожатием Go иначе, чем с браузерным) и запрос по
HTTP/2 или HTTP/1.1, читает до 64 КБ ответа. Среди адресов сервиса есть большие страницы (главная
YouTube, discord.com), чтобы перейти порог заморозки. Сервис открыт, только если все его адреса
ответили **дважды подряд** (`Passes`); время — самый медленный адрес, в среднем по проходам. 8 с на
адрес.

**Через VPN.** Метод `vpn` у сервиса: профилей winws2 для него нет, а правила «Обход DPI: …» этого
сервиса (и голос Discord) получают действие «через VPN» на основной сервер.

**Смена сети.** Пока хоть один сервис в автоматическом режиме и есть подобранные методы,
`zapretWatch` слушает те же уведомления, что «Сети» (`netwatch.Watch` раздаёт их всем подписчикам),
через 4 с после пачки событий и раз в минуту читает ключ сети и при смене пересобирает winws2. Без
подобранных методов сеть не читается: ключ не нужен.

## Супервизор

`Runner` держит один winws2 с последними аргументами: при выходе перезапускает через 2, 4… до 60 с
(после минуты работы — снова с 2 с), хранит 40 последних строк вывода и причину остановки
(последняя строка с error/fail/cannot/invalid). Новые аргументы перезапускают его, те же — нет.
